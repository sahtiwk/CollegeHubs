## Manual local verification

Used disposable MongoDB 7.0.14 replica sets via the existing temporary mongodb-memory-server installation, outside project dependencies. The UI fixture API ran on 127.0.0.1:5099 and Vite on localhost:5177. Only synthetic `example.test` identities and disposable records were used. No production database, real registry activation, or reset command was used.

- Signed in as Plum College and Evergreen Institute fixture users through the normal password UI. Each showed only its own post, name, subject channels, and palette. Fixture users deliberately carried misleading legacy college labels containing `iiit iit`; these never selected membership or branding.
- Default palette displayed plum #310A31, cream #F4ECD6, peach #FFD3B6, pale sky #DFF7FF. Second fixture displayed green #123F34. Abril Fatface headings and Archivo text loaded visibly.
- At 360 x 800, document width equaled viewport width (360), with no horizontal overflow. Opened Menu using Enter. Shift+Tab wrapped from Close to Sign out; Tab wrapped back to Close. Escape closed the drawer and restored Menu focus.
- Opened the mobile profile editor: college appeared as read-only server-provided text; profile fields had accessible labels. Visited college standings and verified the server's own rank and only that college's member.
- Like changed to Unlike with count 1, then unlike succeeded against the real isolated DB.
- Signed in as an unassigned fixture. The explanation rendered without tenant content; assignment retry remained unassigned and showed the configured-domain explanation.
- Desktop layout checked at 1280 x 900. Captured screenshots below. Browser console error log was empty. Temporary viewport override was reset.

A separate disposable branding experiment verified that a palette change without increasing themeVersion is refused. Increasing to version 2 updated the accent to #123F34; repeated provisioning retained one Hub, four channels, the same Hub ID, and an existing DSA sequence value of 7.

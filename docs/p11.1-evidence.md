## Databases and local failure checks

Atlas users have database-wide readWrite only on their own CoreDatabase1, ArcadeDatabase1 or InterviewDatabase1 database. Prior direct probes verified sibling reads are denied. Real commit and abort probes succeeded in all three hosted databases using isolated disposable records, which were removed afterward. Actual feature transactions also passed.

Atlas's unrestricted `0.0.0.0/0` rule was replaced with the current development /32. Render's dashboard-reported Oregon ranges `74.220.48.0/24` and `74.220.56.0/24` are allowed. These are shared provider ranges, not dedicated IPs. All four services remained ready after the change. Update the development /32 when the developer's public address changes; never restore unrestricted access as a routine fix.

Neon has a dedicated `collegehubs_learn_staging` role and `collegehubs_demo_learn_staging` database with schema v2 and reviewed DSA/Web seeds. The role is not superuser and cannot create roles/databases. The preexisting `neondb` has no user tables; its inspection found no readable user table. Mongo services have no PostgreSQL credentials, and Learn has no Mongo credentials.

The full local disposable integration fixture passed **101 tests, zero failures, zero skips**. An initial bare guard invocation lacked fixture configuration and failed four fixture-required checks; rerunning through the documented fixture resolved that setup error. Local disconnected Mongo connection probes returned readiness503 for Core, Arcade and Interview. Disabling only the disposable local Learn database returned Learn503 with all siblings200, then recovered after restoration. These failure injections are local evidence; hosted databases were not intentionally disabled.

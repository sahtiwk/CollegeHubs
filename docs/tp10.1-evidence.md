# TP10.1 — rich progress and safe next actions

Scope: versioned summaries and a five-domain continuation journey on the existing P10 foundation. This is local implementation evidence, separate from the earlier hosted P10 release.

## Changes

- Each module returns schema version 2, minimized counts, freshness and an owned continuation identifier. Learn includes up to five active path versions with required/completed topic counts. No answers, report contents, resume text or arbitrary URLs leave the module.
- Core validates exact schemas, bounds responses to 4 KiB, versions cache keys and retains two workers, shared concurrency of two, the 800 ms aggregate deadline, 60-second freshness and five-minute stale limit. Legacy count-only responses remain readable during rollout.
- Dashboard and Progress use the same path and module cards. Direct actions are constructed from allowlisted route types and identifier formats; stale/unavailable states do not offer those actions. Pending delivery is clearly separate from confirmed Aura.
- Weak-skill DTOs carry the domain. Latest owned finalized assessments on active versions are selected before the low-score filter, within 30 days and at most five. Import rechecks current suggestions before one-use consumption and preserves the owned draft/current Interview session boundary. Generation continues to receive selected labels/version only.

## Verification

The guard suite exercises strict v2 fields, malformed/private data rejection, bounded deadlines, owner-scoped identifiers, current-membership checks, path changes between issue/import, replay rejection and selected topics reaching generation. Existing module lifecycle and reconciliation guards remain included.

`tests/frontend/rich-progress-browser.cjs` uses disposable upgraded Learn and isolated Mongo stores. It checks five actual path summaries and five-domain assessed suggestions through Core, three pending counts, canonical saved activity links, resuming an owned assessment, both Dashboard and Progress, and a 390px viewport. Arcade/Interview completion rows and pending deliveries are synthetic fixtures; stale/unavailable responses are explicitly injected browser fixtures. They do not claim hosted outages or real provider completion.

Verified on 20 October 2026:

- Full local guard suite: **177 passed, zero failed or skipped**.
- Learn TypeScript build and web TypeScript/production build passed. The existing large shader bundle warning remains.
- Browser acceptance passed against live local services, including all five domain suggestions, saved-assessment navigation, three pending delivery counts and stale/unavailable isolation.
- Desktop and 390px mobile previews inspected; no horizontal overflow. Screenshots: [desktop](screenshots/tp10.1-progress-desktop.png), [mobile](screenshots/tp10.1-progress-mobile.png).

No production deployment or new external provider configuration is part of TP10.1.

## Rollout and safe stop

Deploy the compatible Core reader first, then module producers and the UI. No new migration is introduced; five-domain content requires the existing TP8/TP9 Learn migrations. Disable an individual optional read key to isolate a failing widget. Destination routes retain their own ownership checks regardless of any previously displayed link.

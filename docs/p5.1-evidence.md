# P5.1 - authoritative Study Room lifecycle

Local implementation and tests passed on 2026-10-01; completion review finalized 2026-10-02. P5.2 is not started. No hosted deployment, paid dependency, provider account or push is part of this phase.

## Delivered

Core now owns `Problem`, `StudyRoom` and `StudySolution`, two original bounded problem seeds, HTTP room discovery/lifecycle/comparison routes and authenticated study socket operations. Waiting-only admission enforces eight participants; the host starts once with at least two. Database time fixes a 5-60 minute deadline. Immutable snapshots, revision CAS, durable early submit, a shared write fence and one transaction for closure protect acknowledged work. Before closure, even the host receives only their own source. Empty solutions are explicit. Startup, one-second due scans and authorized reads recover overdue rooms. Set `STUDY_ROOMS_ENABLED=false` to disable new rooms while retaining existing work.

See [full API, persistence and operational contract](study-rooms.md). No frontend component or palette changed. P5.2 owns the timer/editor/comparison/review UI and completion award facts. P6 owns live scoring. There is no execution engine or judge.

## Automated evidence

Added boundary guards before implementation. The initial standalone G4 run failed with missing `studyService`, establishing that the new assertions did not pass against P4.2. Final complete fixture run uses disposable local Mongo replica sets, PostgreSQL and actual Core/Learn/frontend processes:

- **72 tests passed, 0 failed, 0 skipped**, G1-G4; final reported duration 18.17 seconds. The local untracked TAP report is `.local/p5.1-guards.tap`.
- G1 adds real HTTP foreign room/channel/problem denial, caller-Hub injection rejection, nonparticipant privacy, host-only start and no pre-close comparison/source disclosure. Existing channel, identity, theme, grant, Learn and Aura guards still pass.
- G4 proves concurrent identical create/start replay, changed creation conflict, safe-stop preserving creation retries, host/minimum-participant checks, and immutable start/end dates.
- Nine competing joins yield exactly seven admitted peers plus the host. Foreign and missing-Hub rooms are hidden, and same-Hub nonparticipants cannot read snapshots.
- Draft revision CAS allows one winner from two tabs; changed replay conflicts. UTF-8 byte bounds, unsupported languages and invalid revisions fail. A Core clock advanced 120 seconds does not change database save timestamps.
- Private snapshots and real socket fanout do not expose peer source. Early submit freezes a revision; repeated submit and lost-ack draft retries are safe. Foreign-Hub and same-Hub outsider socket subscriptions fail.
- A save is deliberately stalled **after its solution update but before its final room fence**, while two close attempts contend. The deadline check rolls back the unacknowledged update and seals the previous acknowledged source once.
- Injected close failure after the first solution write rolls back both room state and all seals; retry closes once with one row per participant.
- Real child Core processes are killed and relaunched against the same DB. An acknowledged submitted source survives active reconnect, a later restart recovers an overdue room before listening, and the running one-second scanner emits a closed snapshot for another room. No restart test relies on an in-memory fake room.

`npm run build` passes all workspaces: Vite web (159 modules), Core source syntax and Learn TypeScript. `git diff --check` passes. No new dependency/lockfile changes.

## Limits and next phase

This is local correctness evidence, not hosted Atlas acceptance or a scale/SLA claim. Source is literal, never executed. Mongo transactions require a replica set. Database commit acknowledgments can arrive after the deadline; the final successful database fence orders the write before closure. Unsent keystrokes are not recoverable. Close processing can lag during host sleep/backlog; the stored deadline still rejects late writes. Scanner batches are bounded at 100. Socket delivery and rate limits are process-local; persistent snapshots repair missed notifications. No source-bearing global broadcast is used.

Inherited dependency advisories, localStorage identity and hosted acceptance remain documented in earlier evidence/P11. The seeded problems support the first demo; broader curricula, moderation, judges, co-editing, peer-review storage, study award events and UI work are outside P5.1. P5.2 remains the next requested sub-phase.

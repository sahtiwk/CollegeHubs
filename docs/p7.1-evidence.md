# P7.1 - independent Arcade and NumberGuess

Local acceptance completed 2026-10-06. Hosted release remains P11-gated. P7.2 is not started.

## Delivered

- Independent `services/arcade` build/start, Mongo connection and readiness. Only pure contracts are shared with Core; no Core models/database access or sibling process import.
- A3 state/grant exchange, pinned RS256 issuer/audience/kid, hashed opaque session, expiry, exact Origin/CSRF, user + Hub ownership, path-restricted cookies. Gateway isolates selected module cookies and strips Core/browser bearer credentials for module routes.
- Actual legacy NumberGuess flow ported into the shared React router/shell. Ten server-authoritative guesses, hints/history, crypto-random private target, ten-minute deadline, ordered actions, identical replay and changed-replay conflict. No browser-selected score or secret target.
- Win and stable pending event are stored in one transaction. Bounded service-authenticated delivery, lease/backoff, read-triggered retry and direct operator reconcile preserve the event/receipt across failures.
- Core persists prospective `arcade-numberguess-v1`: only NumberGuess enabled, first successful game/day = 5, repeat same-game win/day = 0. Existing shared balance/day/streak authority is retained. MathAmplitude/sorting remain unavailable.
- Existing plum/cream/peach/sky tokens and Archivo/Abril Fatface remain in use. Original rights notice and source are retained; legacy App/router/Navbar/global CSS/AIChatbox/OpenAI do not enter active builds.

## Verification

`npm run build`: web TypeScript/Vite, Arcade syntax, Core syntax and Learn TypeScript passed. The exact Arcade deployment build (`node deploy/build.mjs arcade`) passed in an isolated `.local/p71-build-arcade` copy using only Arcade/contracts production dependencies. No hosted deployment was run. Its dependency audit reports two moderate findings; this phase does not claim a dependency-security certification.

Full disposable fixture guards: **85 passed, 0 failed, 0 skipped** (clean `.local/p32-guards.tap`; 8.99 seconds). New assertions were added to existing G2/G3 areas before the implementation; no extra test suite was introduced. The fixture now refuses overlapping guard runs so reports cannot interleave.

Coverage includes:

- Real Core -> shared gateway -> Arcade bootstrap, foreign Origin/state replay denial, cookie properties, session expiry/logout, missing session and forged CSRF.
- Same-Hub other owner and other-Hub reads/actions return 404; browser query selectors and posted score/Aura fail.
- Integer/range/sequence validation, simultaneous identical actions returning the same transition, altered action conflict, ten-guess loss, expiry and terminal replay.
- No target/access binding in game DTOs. First win records exactly 5 canonical Aura; a second successful game records zero and leaves balance unchanged. Unreleased MathAmplitude facts stay inactive.
- Real Core commit followed by simulated lost HTTP reply leaves the identical event pending. Immediate retry honors backoff; due reconciliation restores the exact original receipt without increasing Aura.
- Existing Hub isolation, native Aura, Study lifecycle/recovery and schedule guards also pass.

An early game-save check found a Mongoose immutable-field default failing during hydration. Rules version is now explicitly assigned on creation and required thereafter; the concurrent/replay guard passes. Initial failed/interleaved reports were superseded by the clean run above.

## Operation and limits

See [Arcade setup/contracts/recovery](arcade.md) and [free deployment setup](../deploy/README.md). Local Core/Arcade/Learn default ports are 5000/5001/5003; fixture ports are separate. Disabling new Arcade games preserves saved reads/recovery. Readiness depends only on Arcade's own DB.

Free Render configuration now includes an independently deployable Arcade service. Account setup, actual origins, restricted hosted DB credentials, TLS/cookie behavior and free workspace quotas remain unverified hosted tasks. Pending delivery needs due reads or authenticated operator recovery; free sleeping services have no always-on delivery guarantee. Current membership and retained issuance remain mandatory for Core awards. Validated gameplay does not prove human play. Human game review and hosted secrets remain the user's deployment/review role.

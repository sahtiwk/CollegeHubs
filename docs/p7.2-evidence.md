# P7.2 - three Arcade games and catalogue

Local acceptance completed 2026-10-07. Hosted release remains P11-gated. P8.1 is not started.

## Delivered

MathAmplitude ports the source arithmetic/score/feedback/timed-round flow. The service issues private-answer questions and stores ordered answer attempts; the browser receives only its current question. A 60-second server deadline rejects late answers, five correct answers and at least 30 seconds qualify, three wrong attempts skip a question, and finalization atomically stores one immutable result/event. Fresh rounds reset score, input, feedback and clock; intervals clean up on navigation. No local high score or browser grading drives Aura.

Sorting Complexity is a new constrained bubble-sort exercise: six crypto-random distinct values, all 15 adjacent comparisons, swaps only after an inverted comparison, and the correct worst-case quadratic choice. The complete permutation-preserving trace is validated and saved with at most 31 accepted actions. No arbitrary code, eval, client arrays or posted scores are accepted. It has a ten-minute deadline and no extra minimum duration.

`packages/contracts/arcade-games.json` is the shared pure manifest. API create/descriptor availability and frontend catalogue/lazy game selection consume it. NumberGuess, MathAmplitude and Sorting are the only ranked games. Other legacy entries remain unavailable and cannot start/emit rewards. Casual play would earn zero; no casual game is released. Existing shell, auth, theme and error boundary are reused. Each game is a separate lazy chunk; no legacy App/router/Navbar/global CSS/AI client/WebGL is imported. Source rights/notices remain intact.

Core retains immutable P7.1 rules and adds `arcade-three-games-v1` prospectively. Occurrence selects the latest active policy with matching game/rules version. Shared per-user/day counters and receipts are retained, never reset/backfilled. First qualifying completion of each game/day = 5; repeats = 0; three released games total at most 15/day. Pending delivery/reconciliation uses unchanged stored envelopes and the existing lease/backoff/service authority.

## Operation and limits

See [Arcade contracts](arcade.md) and [deployment](../deploy/README.md). Preserve both rule versions, game records and Core ledger. Deploy Core policy before enabling new games for users; old Core keeps new-game results pending, and facts preceding activation cannot be retroactively awarded. The existing new-game disable flag preserves saved results/recovery. Core/Arcade retain separate processes/DB ownership and free deployment artifacts.

Hosted URLs/accounts/restricted DB users/TLS/free quotas remain unverified P11 work. Sleeping free services need due reads or service-only recovery; no delivery SLA is claimed. Validation does not prove human play or cognitive benefit. Human product/game review remains useful; no external publication/deployment was performed.

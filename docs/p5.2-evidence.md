# P5.2 - solve, reconnect, compare and review

Local PASS, 2026-10-02. P6.1 is not started. Live scoring and hosted acceptance remain gated to their planned phases.

## Delivered behavior

Each channel links to a Study Room lobby. Create a waiting room, join it as a peer, let the host start, solve privately, save explicit revisions, optionally submit early, then compare sealed work and publish one permanent review per peer. These routes stay inside the existing Hub shell and use the shared plum/cream/peach/sky tokens. No independent frontend, redirect, editor service, paid dependency or execution engine was added.

The editor distinguishes unsaved, pending, saved, conflicting and frozen work. An unconfirmed save keeps its exact revision/payload for retry. Newer server revisions preserve conflicting local text with explicit resolution choices. A DB-time sample anchored to the browser's monotonic clock drives the timer. Reconnect, focus and five-second sync recover persisted state; the displayed deadline disables writes while the backend remains authoritative. Source and reviews remain literal React text, using the existing allowlisted code highlighter.

Core PeerReview storage enforces current participant/Hub/room/solution scope, closed-room-only access, no self-review, an 8 KiB bound and immutable semantic replay. At closure, qualifying acknowledged solutions acquire stable completion IDs and pending status. Due/startup/owned reads reconcile native facts in bounded transactions. Empty drafts are ineligible. Live records become `rules_inactive`; no real Aura points are awarded yet. See [full contracts and limits](study-rooms.md).

## Limits

Unsent edits are tab-local and can be lost on navigation/reload; explicit save is required. No co-editing, judge, code execution or correctness score exists. Socket delivery and rate limits remain process-local; snapshots repair missed events. The timer is a latency-adjusted display estimate; Mongo fences decide admissibility. Free-host sleep can delay closure/reconciliation but cannot extend deadlines. Existing inactive facts are not retroactively scored; P6 must define activation policy. Earlier dependency advisories, localStorage auth and P11 hosted acceptance remain unchanged.

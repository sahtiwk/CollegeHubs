# Free staging deployment

Status: configuration prepared; no account, public deployment or URL verified. Local UI acceptance passed; hosted acceptance is still required before release. `cvr.ac.in` is the membership domain; use free `pages.dev` / `onrender.com` hostnames for hosting.

1. Sign into Cloudflare Pages, Render, Atlas and Neon with your own accounts/MFA. Select Free, without paid upgrades. Connect this repository when ready to publish. No friend's deployment or credentials are needed.
2. Atlas: create a Free cluster and a Core-only database user restricted to its database. Use TLS and restrict network access to service outbound ranges. Neon: create a Free project and a fresh database named `collegehubs_demo_learn_staging`, with Learn-only credentials. Do not use Render's expiring free PostgreSQL for retained data.
3. Create a Pages project to get its assigned HTTPS origin. Set **root directory `apps/web`**, Node `24.12.0`, build command `cd ../.. && npm ci --include=dev && npm run build:web`, output `dist` relative to that root. Functions are under `apps/web/functions`; the build uses the root workspace lock. Add `CORE_API_ORIGIN`, `LEARN_API_ORIGIN` and `ARCADE_API_ORIGIN` when Render assigns them. `_routes.json` excludes UI/assets from Functions. No top-level 404 page or custom college domain is needed.
4. Import root `render.yaml`. It defines three Free web services, independent filters, no disks/databases/workers/cron/paid previews. Keep repo-root build context. Builds install only the selected service and contracts. Learn compiles TypeScript then prunes build dependencies.
5. Fill the provider settings from each service's `.env.example`. Core `APP_ORIGIN`/`ALLOWED_ORIGINS` and Learn `APP_ORIGIN` must equal the Pages HTTPS origin. Learn `CORE_API_BASE_URL` is Core's public HTTPS origin. Generate a local RSA keypair of at least 2048 bits. Core gets the private key, JWT secret, Mongo URI and public-key JSON map. Learn gets only the matching public key/key ID, its own service key and PostgreSQL URI. Keep keys in ignored local files/provider settings, never frontend variables.
6. With the explicitly selected Core `MONGO_URI`, run `npm run provision:hubs -w @collegehubs/core`; repeats preserve one CVR Hub/four channels. Feed JSON containing `service`, `keyId`, `key` on stdin to `services/core/scripts/provisionModuleService.js`. Use service `learn`; key ID 8–64 URL-safe characters; key = key ID + `.` + 32 random bytes in base64url. Core stores only its hash; put the original in Learn's `CORE_SERVICE_KEY`. No paid remote shell is needed.
7. For the empty Learn demo DB, locally set `DATABASE_URL`, `DEMO_RESET_ENABLED=true`, `DEMO_DB_NAME_ALLOWLIST=collegehubs_demo_learn_staging`, with `NODE_ENV` unset/development. Run `node services/learn/scripts/setup_demo.ts --confirm=collegehubs_demo_learn_staging --disposable-data-only`. It refuses existing tables and never drops them. Remove reset settings afterwards. This is not a production migration command.
8. Deploy Core/Learn/Arcade and verify each `/health/ready`, then configure and deploy Pages. `ENABLE_MODULES=learn,arcade` after Arcade configuration; Interview stays unavailable. Future sockets go directly to `VITE_CORE_SOCKET_ORIGIN` (Core `/socket.io`, namespace `/core`), not this HTTP gateway.
9. Copy `origins.example.json` to ignored `.local/deployment-origins.json` and record real assigned origins. Complete the hosted checks in `docs/learn-spike.md` before marking hosted PASS.

The user owns accounts, enters secrets and authorizes repository access; the assistant can prepare code/configuration, diagnose failures and verify assigned URLs. No passwords need to be shared in chat.

Render's workspace hours are shared across services. This design targets intermittent demos with sleep/cold starts, no keepalive jobs or paid fallback. Account eligibility, quotas and cold starts remain hosted checks. Official limits are in plan H1–H4.

## P7.1 Arcade setup

Create a separate logical Arcade Mongo database and an Arcade-only database user restricted to that database on the existing Atlas cluster. Put its URI only in Arcade's `ARCADE_MONGO_URI`. It must support transactions. Never reuse Core's database/user. The Render Arcade entry builds only its workspace/contracts and listens on Render's assigned PORT. It receives the Core public key, key ID, issuer `collegehubs-core`, audience `collegehubs-arcade`, public Core API base URL and matching APP_ORIGIN.

Provision a distinct Arcade service key with the existing stdin tool. Supply `service: "arcade"`, `keyId`, `key`, and `eventTypes: ["arcade.game_completed"]`. Learn credentials remain without event scopes. Set the original Arcade key as its `CORE_SERVICE_KEY`. Generate another independent 32-byte base64url value (43 characters) for `ARCADE_RECONCILE_KEY`; it is only for direct service recovery, never browser/gateway configuration. Do not print keys or paste them in chat. Enable Arcade in Core and point Pages ARCADE_API_ORIGIN to its assigned HTTPS origin. Startup records the prospective NumberGuess Aura policy before accepting traffic.
